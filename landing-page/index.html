Built Around a Runtime, Not Just an Integration.

Enterprise Messaging Is More Than Sending Messages

Businesses quickly outgrow basic messaging integrations. As messaging volume increases, organizations face delivery failures, provider limitations, missing observability, and operational complexity. RelayRuntime solves these challenges by introducing an enterprise messaging runtime.

Single Provider Dependency

Tight coupling to one provider locks workflows and blocks change.

No Retry Engine

Failed deliveries disappear without structured recovery policies.

No Campaign Record

Ad-hoc send buttons leave no campaign history operators can review.

No Monitoring

Operators cannot see which contacts were sent, failed, or skipped.

No Delivery Analytics

Without delivery analytics, teams cannot measure or improve reliability.

Manual Operations

Manual interventions do not scale when messaging becomes mission-critical.

Key Features

Built around campaign operations for Odoo Community — bulk sending, operator retry, a delivery dashboard, and Green API live sending.

Provider Setup

One active provider per company. Green API sends live messages. Mock Provider simulates sends for testing. Additional provider adapters are registered and are not available for live sending in this release.

Campaign Execution

Each campaign runs in the operator's request, recipient by recipient, with delays and a delivery log for every contact. This release does not include a background queue.

Operator Retry

From a finished campaign, use Retry Failed Recipients. RelayRuntime opens a linked retry campaign for failed and skipped contacts and sends it immediately. Retry does not run in the background.

Bulk Messaging

Run bulk campaigns from the Command Center, with attachments, product catalogs, and a delivery log for every contact.

Delivery Dashboard

The Delivery Dashboard totals internal send results: sent, failed, and skipped, based on the provider's HTTP response. It does not show WhatsApp delivered or read receipts.
