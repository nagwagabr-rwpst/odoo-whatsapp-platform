RWPST RelayRuntime

Enterprise Command Center for operational messaging on Odoo 19

Module version 19.0.6.1.0 · Odoo 19 Community · License LGPL-3

Overview

RWPST RelayRuntime is a production-oriented WhatsApp campaign execution runtime for Odoo with an enterprise Command Center experience. It coordinates outbound campaigns with execution lineage, lease-aware concurrency, and recovery-oriented persistence—so operational messaging stays correct under failure, not merely a one-shot send button.

Each bulk run creates a durable whatsapp.bulk.execution attempt with heartbeat and lease metadata. Campaigns remain the business-facing aggregate; executions are the runtime authority.

Enterprise UI

  • Command Center with KPIs, alerts, and workspaces
  • Enterprise navigation: Operations / Analytics / Configuration
  • Delivery Dashboard and Live Campaign Monitor
  • RWPST brand theme across backend screens

Runtime features

  • Replay-safe recovery and stale execution reconciliation
  • Resilient batch execution with outbound intent persistence
  • Lease-safe worker orchestration and heartbeat liveness
  • Retry lineage tracking (parent → child campaigns)
  • Attachment and product-catalog orchestration
  • Operational diagnostics via message logs and executions

Features

  • Bulk send from Contacts with attachments and product catalogs
  • Campaign monitor (kanban with periodic refresh)
  • Retry failed/skipped recipients as child campaigns
  • Delivery logs, dashboards, and sale order workflow hooks
  • Provider adapters: Green API and Mock Provider (send-capable)
  • Mock Provider for QA without sending real WhatsApp messages

External WhatsApp provider accounts (for example Green API) are required for live delivery. Mock Provider is included for safe testing.

Limitations (read before production)

This module does not guarantee exactly-once delivery to WhatsApp. Provider APIs are external to PostgreSQL; HTTP rollbacks and retry campaigns can produce duplicate messages. Large bulks run in a single long transaction and may hit server timeouts.

  • No built-in background queue or cron bulk worker
  • No inbound webhook HTTP controllers (skeleton only)
  • Most alternate providers are UI placeholders — Green API and Mock are send-capable
  • Multi-worker deployments should follow the production checklist in documentation

Installation

  1. Add the parent of the relayruntime module folder to addons_path (installable package name: relayruntime).
  2. Update the Apps list and install RWPST RelayRuntime.
  3. Or from the CLI: odoo-bin -c odoo.conf -d YOUR_DB -i relayruntime
  4. Assign WhatsApp User / Manager groups.
  5. Configure WhatsApp → Settings. Use Mock Provider on non-production databases; use Green API for live sends.

Dependencies: base, sale, mail, product. Odoo 19.0 Community. Module version 19.0.6.1.0.

Upgrading from the former whatsapp_simple technical name? Read MIGRATION.md before production.

Support

Standard support covers documented runtime behavior on Odoo 19 Community: defects in shipped code, install/upgrade guidance, and Mock Provider reproduction.

Out of scope: provider outages, exactly-once delivery SLAs, distributed HA runtime, and custom forks that bypass lease or idempotency controls.

Report issues via the project repository issue templates (Bug, Runtime Corruption, Duplicate Send, Deployment). Security reports follow SECURITY.md only.
